## 实现要点

### 表示与 ABI
- 内存：两个相邻 DWORD，小端（低 32 位在低地址）
- 寄存器对：EAX=低、EDX=高；返回值 EDX:EAX
- 参数：cdecl 栈上两连槽（lo 低地址）；ArgSlots(size8)=2
- 单寄存器 result 约定：值 = 寄存器(低):EDX(高)

### 运算序列（compile/arch/x86/exp.go compileBinOp64）
- add/sub：add/adc、sub/sbb
- mul（低64位）：lo*lo + (lo*hi + hi*lo)<<32；保护 EBX/ESI/EDI/ECX
- div/mod：恢复余数移位减法循环（任意 64 位除数），商=QUOT(EBX:槽)、余=REM(ESI:EDI)
- 操作数协议（右为复杂表达式时统一）：左装入 EDX:EAX → 压栈 → 右算入 EDX:EAX → 弹左到 EBX:ECX
- 比较：复用既有 compileCond64（无符号 ja/jb 系列）

### 编译器接线
- generate()：ps==4 且 Type 为 u64/i64 时路由 arch.Compile64Type
- Assign：u64 目标变量分流（字面量可能不带 64 类型）；地址剥宽度前缀
- checkBuiltin：copy(dst,src) 同 Kind 校验；new(list) 返回列表值类型
- storeVal/leaf：>imm32 常量 movabs 中转 / 双 DWORD 拆分（阈值 0x7FFFFFFF，防符号扩展）

### sliceExp 重写（关键教训）
基址寄存器跨嵌套子表达式存活不可依赖分配器：
1. Force 绑定后 allocRegAvoid 仍不感知（其 avoid 表基于 BindIndex 懒赋值）——架构债
2. 因此非常量边界（x86 一律；x86_64 仅枯竭时）走**栈中转序列**：
   sub sp,3*ps 预留 R.ptr/R.len/R.cap；lo 暂存于 cap 槽；base 重算折叠；
   len=hi−lo、cap=origCap−lo 均经栈引用；槽距全部 ps 参数化（杜绝硬编码 +4/+8）
3. 常量边界走原寄存器路径（x86_64 主路径）

### 类型宽化提升（parser/exp_check.go checkArith）
float→f64；否则**宽类型获胜**（右 Size > 左 Size 时取右）。修复 int×u64 被推导为 int。

1. **i64 有符号除法/比较未实现**（u64 无符号已完成；parse 负数年份等场景受限）

3. **allocRegAvoid 不感知 Reg.Force 绑定**（架构债；sliceExp 以物理栈保护绕开，
   其它跨 generate 持有值的场景仍靠约定）
